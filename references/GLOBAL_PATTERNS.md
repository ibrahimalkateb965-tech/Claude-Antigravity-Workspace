# القواعد المعمارية العالمية (Global Patterns)

> [!CAUTION]
> **تم تدقيق هذا الملف معمارياً.** يمنع استخدام الترقيعات السطحية (Band-Aids). جميع القواعد هنا مصممة لضمان أمان وموثوقية النظام والأنظمة الفرعية على مستوى بيئة الإنتاج الفعلي.

# 🌍 الأنماط الهندسية العالمية للوكلاء (Android Global Patterns)

> **قاعدة صارمة للوكلاء:** يجب تطبيق هذه الأنماط بشكل افتراضي في أي مشروع أندرويد لتفادي الأخطاء المعمارية الشائعة.

## 1. تجنب التقاط الحالة القديمة في Compose (Stale State in LaunchedEffect)
- **المشكلة:** الاعتماد على متغيرات محلية ملتقطة داخل كتل غير متزامنة مثل `LaunchedEffect` أو `snapshotFlow` يؤدي لمعالجة بيانات قديمة (Stale Data) وانهيار التطبيق (Crash) أو دخوله في حلقة لا نهائية.
- **النمط العالمي:** يجب قراءة القيمة الحية مباشرة من مرجع الـ State داخل كتلة `collect` (مثال: `viewModel.uiState.value.property`)، والاعتماد على أوامر تغيير الحالة المطلقة بدلاً من الحسابات النسبية المبنية على الحالة القديمة.

## 2. إدارة تنازع الصوت التلقائي مع قوارئ الشاشة (Audio Focus & Accessibility)
- **المشكلة:** محاولة إدارة التركيز الصوتي يدوياً عبر الكود للتوقف عند نطق TalkBack معقدة جداً وعرضة للأخطاء.
- **النمط العالمي:** تغيير `ContentType` لأي مشغل صوتي (مثل ExoPlayer) إلى `C.AUDIO_CONTENT_TYPE_SPEECH`. هذه الميزة المدمجة تجبر المشغل على الانخفاض/الإيقاف المؤقت تلقائياً عندما يتحدث المساعد (Ducking)، وتستأنف فور سكوته.

## 3. محاكاة خدمات النظام في اختبارات الوحدة (Mocking System Services)
- **المشكلة:** حقن Context يحمل `getSystemService` يسبب `ClassCastException` عند استخدام مكتبات محاكاة مثل MockK.
- **النمط العالمي:** يجب دائماً عمل Mock صريح للخدمة المطلوبة وإرجاعها بشكل محدد عند طلبها من الـ Context الوهمي لتفادي فشل الاختبارات.

## 4. أمان أندرويد 11+ للخدمات المدمجة (Package Visibility)
- **المشكلة:** فشل استدعاء الخدمات المدمجة كـ (SpeechRecognizer أو TextToSpeech) مباشرة بسبب قيود الرؤية الأمنية.
- **النمط العالمي:** يجب دائماً إضافة علامة `<queries>` للخدمات أو الحزم المطلوبة في ملف `AndroidManifest.xml` للسماح بالوصول للخدمات المستهدفة صراحةً.

## 5. تسريع اكتشاف انقطاع الإنترنت (Fail-Fast Network Strategy)
- **المشكلة:** عند انقطاع الإنترنت، يظل التطبيق صامتاً ومجمداً لفترة طويلة (حتى 10 ثوانٍ) بانتظار استجابة الخادم قبل إعلان الفشل.
- **النمط العالمي:** تخفيض `connectTimeout` و `readTimeout` في طلبات جلب الروابط (مثل Retrofit أو OkHttp) إلى `4000ms`. هذا يسرع الإعلان عن انقطاع الإنترنت وتفعيل واجهة الخطأ (Offline UX) بشكل شبه فوري.

## 6. فصل المشاريع بشكل آمن باستخدام Git (Clean Forking)
- **المشكلة:** الحاجة إلى استخراج نسخة قديمة (Commit محدد) من تطبيق ليكون أساساً لتطبيق جديد تماماً، مع الحفاظ على أمان التطبيق الأصلي.
- **النمط العالمي:** لا تستخدم أوامر الأرشفة المعقدة؛ قم بنسخ المجلد بـ `git clone`، ثم العودة للنسخة المستهدفة بـ `git checkout <hash>`، ثم إزالة المجلد المخفي `.git` نهائياً، وإعادة تهيئة مستودع جديد بـ `git init`. 

## 7. استراتيجية توزيع نماذج الذكاء الاصطناعي (Model Allocation Strategy)
- **المشكلة:** استخدام نموذج واحد ثقيل لكل المهام يبطئ العمليات السريعة ويزيد التكلفة بشكل مفرط.
- **النمط العالمي:** يجب تخصيص النماذج القوية (مثل Opus/K3) للمهام المعمارية والبرمجية المعقدة، بينما يتم تخصيص النماذج السريعة (مثل Haiku/K2.7) للمهام الفرعية وأدوات الخلفية والاستفسارات السريعة.

## 8. حل تعارض مصادقة 401 عبر المترجم المحلي (API Proxy Routing)
- **المشكلة:** فشل المصادقة (401) عند استخدام أدوات تفرض صيغة (Anthropic) بينما مفتاح الـ API يتبع صيغة (OpenAI Compatible) كـ Kimi.
- **النمط العالمي:** تشغيل خادم `LiteLLM` في الخلفية ليعمل كمترجم محلي (Proxy) يحول الطلبات بين الصيغتين، وتوجيه أداة التطوير لتقرأ من الخادم المحلي `http://localhost:4000`.

# قواعد البنية التحتية والبيئات التشغيلية (Infrastructure & Environments)

## 1. قواعد نظام التشغيل والأتمتة (Windows & PowerShell)
* **استقرار نقل الملفات ومعالجة الترميز (CRITICAL FIX):** يُمنع التحايل على تجميد `Move-Item` باستخدام سكربتات بايثون خارجية كترقيع سطحي. السبب الجذري هو تعارض الترميز. **يجب** وضع الأمر `$OutputEncoding = [console]::InputEncoding = [console]::OutputEncoding = New-Object System.Text.UTF8Encoding` في بداية أي سكربت PowerShell للتعامل مع الرموز العربية والـ Emoji بشكل آمن ومحلي.
* **التعامل مع تعارض العمليات (CRITICAL FIX):** الإغلاق القسري العشوائي باستخدام `taskkill /F /PID` هو ممارسة مدمرة وقد تقتل عمليات حيوية. لمنع تعارض بوتات تليجرام أو الوكلاء، **يجب** بناء نظام "أقفال الملفات" (Mutex File Locks) أو ربط المنافذ (Socket Binding) لضمان أن نسخة واحدة فقط من البوت هي التي تعمل، مع إدارة دورة حياتها برمجياً (Graceful Shutdown).
* **استقرار التحميل:** استخدام `Start-BitsTransfer` مع تفعيل بروتوكول TLS 1.2 لدعم استئناف التحميل ومنع أخطاء الانقطاع الخاصة بـ `Invoke-WebRequest`.
* **صلاحيات تنظيف الأقراص (C Drive Optimization):** يحظر تماماً المساس بمجلدات قواعد البيانات مثل `C:\Program Files\Microsoft SQL Server`. قواعد البيانات الثابتة (مثل P6 SQLite) يتم عمل نسخ احتياطي لها مسبقاً.
* **الترميز العربي (Python):** نصوص بايثون التي تطبع مخرجات يجب أن تبدأ بفرض ترميز UTF-8 عبر `sys.stdout = codecs.getwriter('utf-8')(sys.stdout.detach())` لمنع خطأ الـ `cp1252`.

## 2. قواعد الويب والاستضافة (Web Hosting)
* **استضافة ماركداون:** موقع GitHub Pages يستخدم Jekyll الذي يخفي المجلدات المخفية. يجب وضع ملف `.nojekyll` فارغ في جذر المستودع لإظهار ملفات Markdown والوثائق بكل محتوياتها بسلام.

## 3. تكامل قواعد البيانات والمخدمات (Backend Integration)
* **معرفات العلاقات (Relations in PocketBase):** عند تسجيل علاقات جديدة، يجب تمرير مُعرّف الكيان الأساسي (الـ ID المكون من 15 حرفاً) كمرجع للعلاقة، وليس اسمه لتجنب رفض الخادم بـ `400 Bad Request`.
