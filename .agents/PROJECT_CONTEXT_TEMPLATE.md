## 3. اتفاقيات التسمية والتنظيم (Naming & Structure Conventions)

### 3.1 هيكل المجلدات (Directory Structure)
```
[root]
  ├── data/            # الجداول، قواعد البيانات، المستودعات (Repositories)
  ├── domain/          # نماذج البيانات (Models)، حالات الاستخدام (Use Cases)
  └── ui/              # الشاشات (Screens)، المكونات (Components)، التنقل (Navigation)
```

### 3.2 قواعد التسمية
- **الملفات والمكونات:** شاشات Compose تنتهي بـ `Screen` (مثال: `QuranProgressScreen.kt`).
- **المكونات الصغيرة:** تنتهي بـ `Card`, `Item`, `Button` إلخ.
- **حالات الاستخدام:** تبدأ بفعل وتنتهي بـ `UseCase` (مثال: `SaveReadingSessionUseCase.kt`).
- **قواعد البيانات:** الجداول والأعمدة تستخدم `snake_case`.

## 4. قيود برمجية صارمة (Hard Coding Constraints)

* **دعم RTL:** تخطيط الواجهات يجب أن يدعم الاتجاه من اليمين إلى اليسار (RTL) تلقائياً، والالتزام بمحاذاة النصوص والترقيم العربي الفصيح.
* **تجنب التكرار (DRY):** يُمنع تماماً نسخ الأكواد، ويجب عزل المنطق المشترك في كلاسات أو دوال مساعدة.
* **معالجة الأخطاء:** لا يُسمح بـ `catch` فارغة. يجب معالجة كافة الاستثناءات وعرض رسائل خطأ واضحة للمستخدم مع خيار إعادة المحاولة.
* **تأمين البيانات:** البيانات الحساسة والمفاتيح السرية (API Keys) لا تُحفظ في الكود بل في متغيرات البيئة.
